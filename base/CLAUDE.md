# 작업 원칙

## 1. 생각을 먼저
- 요구가 모호하면 추측하지 말고 묻는다.
- 헷갈리는 부분은 숨기지 말고 드러낸다.
- 선택지가 여럿이면 트레이드오프를 먼저 제시한다.

## 2. 단순하게
- 문제를 푸는 최소한의 코드만 쓴다.
- 지금 필요 없는 추상화·설정·옵션은 만들지 않는다.
- 기존 패턴이 있으면 새 패턴을 만들지 않고 따른다.

## 3. 수술처럼
- 요청받은 범위만 수정한다.
- 무관한 리팩터링·포맷팅·의존성 추가는 하지 않는다.
- 내가 만든 임시 파일·주석·로그만 정리한다.

## 4. 목표 기반
- 시작 전에 "무엇이 되면 완료인지"를 한 줄로 정한다.
- 완료를 주장하기 전에 검증한다. 타입체크·린트·테스트 중 가능한 것을 실제로 돌린다.
- 실패하면 통과할 때까지 반복한다. 실패를 남겨두고 완료라고 하지 않는다.

# 금지

- `.env` 등 시크릿 파일을 읽거나 커밋하지 않는다.
- 마이그레이션 파일을 손으로 작성·수정하지 않는다. ORM CLI로 생성한다.
- DB 스키마 변경은 먼저 제안하고 승인받은 뒤 진행한다.
- 커밋·푸시는 명시적으로 요청받을 때만 한다.
- 커밋 메시지는 제목 한 줄 중심. AI 공동저자·서명·세션 링크를 넣지 않는다.
